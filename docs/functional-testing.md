# Сценарий функционального тестирования

**ID документа:** QA-FUNC-001
**Цель:** проверка критических пользовательских потоков электронного журнала с UI и API.
**Область:** вход/сессии, права, ученики, оценки, посещаемость, поведение, админка, Excel, mobile UI.
**Не является:** разрешением на запись/импорт/миграции в production.

## 1. Условия и безопасность

### Среда

Предпочтительно использовать локальный или отдельный QA backend и отдельную временную PostgreSQL/Supabase базу. Минимальный автоматический интеграционный сценарий требует `TEST_DATABASE_URL` и подготовленного demo seed. Для ручных тестов используйте demo аккаунты, приведённые в [базе данных](database.md); они не должны существовать в production.

- Перед началом подтвердите URL интерфейса, URL API, branch/build и идентификатор тестовой базы.
- Убедитесь, что тестовая база изолирована и её можно сбросить. Никогда не сбрасывайте production.
- Используйте новый тестовый email для приглашения.
- Не помещайте реальные персональные данные, пароли и access/refresh-токены в отчёт или скриншоты.
- Создание оценок, отметок, приглашений, ролей и Excel-импорт — записи данных. Выполняйте эти пункты только в QA среде с разрешением владельца.
- До импорта/генерации сохраните состояние: QA database backup либо fixture snapshot. Для production сначала запросите отдельное одобрение, план rollback и окно работ.
- Удаляйте созданные тестом данные адресно, по собственным тестовым идентификаторам. Не запускайте широкие `DELETE` в общей базе.

### Базовая подготовка

1. Применить SQL migrations к отдельной QA базе в правильном порядке.
2. Загрузить локальный seed только намеренно. `supabase db reset` пересоздаёт базу и уничтожает её содержимое.
3. Запустить backend с `DATABASE_URL`, уникальным секретом `JWT_SECRET` (не менее 32 случайных байт), `ALLOWED_ORIGINS` и `PORT`.
4. Отдать каталог `web` локальным HTTP сервером; разрешить его origin в `ALLOWED_ORIGINS`.
5. Открыть `/healthz` API и подтвердить ответ 200. Это подтверждает health/DB connectivity, но не логин и не наличие каждой feature-таблицы.
6. Зафиксировать build/commit и версию миграций в отчёте.

## 2. Результат шага

Каждый тест отмечается как **PASS**, **FAIL**, **BLOCKED** или **NOT RUN**.

- PASS — результат соответствует ожидаемому.
- FAIL — фактический результат отличается; приложить сокращённый безопасный запрос/ответ и шаги воспроизведения.
- BLOCKED — шаг нельзя выполнить из-за отсутствующей роли, fixture, миграции или среды.
- NOT RUN — шаг не выполняли; указать причину.

Не считать отсутствие сообщения об ошибке доказательством успеха. Записывать конечное состояние, HTTP статус (если есть), шаг воспроизведения и не-чувствительные доказательства.

## 3. Матрица функциональных тестов

### A. Запуск и публичные страницы

| ID | Действие | Ожидаемый результат |
|---|---|---|
| A-01 | Открыть главную страницу в чистой сессии | Появляется форма входа; нет ошибок загрузки JS/CSS в Console |
| A-02 | Перезагрузить страницу без входа | Форма входа остаётся доступна; приватный маршрут не раскрывает данные |
| A-03 | Перейти к `/healthz` API | 200 и статус `ok`, если БД доступна; при недоступной БД сервер даёт безопасный 503 |
| A-04 | Вызвать защищённый endpoint без токена | 401/unauthorized; чувствительные данные не возвращаются |
| A-05 | Запустить неразрешённый Origin (QA только) | CORS не даёт стороннему origin читать ответ |

### B. Вход, refresh и приглашение

| ID | Роль/действие | Ожидаемый результат |
|---|---|---|
| B-01 | Ввести корректные учётные данные QA пользователя | Успешный вход, UI показывает имя/роль; токены сохраняются согласно реализации |
| B-02 | Перезагрузить страницу после входа | Сессия и текущий пользователь восстанавливаются; приватный раздел остаётся доступным |
| B-03 | Ввести неправильный пароль | 401; понятное сообщение; пароль не отображается в URL/логах клиента |
| B-04 | Дождаться истечения/смоделировать 401 access-token | Клиент вызывает refresh, сохраняет ротированную пару токенов и повторяет исходный запрос один раз |
| B-05 | Выйти, затем открыть защищённый раздел | Токены очищены, пользователь разлогинен, приватный API не доступен |
| B-06 | Администратор создаёт одноразовое приглашение в QA | Возвращён токен только при создании; приглашение появляется в списке |
| B-07 | Новый пользователь принимает действительное приглашение | Аккаунт активирован с ожидаемой ролью; вход работает |
| B-08 | Повторно использовать принятое/отозванное/просроченное приглашение | Операция отклонена; второй аккаунт не создаётся |

### C. Проверка ролей и изоляции

Используйте отдельные аккаунты student, teacher, class_teacher, admin. Не выдавайте тестируемому пользователю больше ролей, чем требуется тестом. Проверьте API и интерфейс.

| ID | Роль/действие | Ожидаемый результат |
|---|---|---|
| C-01 | Ученик запросит список оценок | Возвращаются только оценки его `student_id` |
| C-02 | Ученик запросит оценки другого ученика/попробует их изменить | Чужие данные не возвращаются, изменение отклонено |
| C-03 | Учитель открывает неназначенный класс/предмет | Доступ запрещён; прямой API вызов также запрещён |
| C-04 | Классный руководитель открывает назначенный класс | Доступна read-only сводка; нет формы добавления/редактирования оценки |
| C-05 | Администратор открывает школьный класс и список учеников | Видит полный контекст школы, а не собственную student-карточку/пустой список |
| C-06 | Администратор работает с оценками | Может просмотреть школьные оценки и создать/изменить оценку в корректном учебном контексте |
| C-07 | Администратор работает с посещаемостью | Может видеть учеников выбранного школьного класса и сохранять отметки |
| C-08 | Администратор имеет одновременно `admin` и `student` | Админ-ветви имеют приоритет; его не ограничивают собственным ученическим профилем |
| C-09 | Удалить/изменить роль учителя или отключить аккаунт (QA) | Права обновляются; отключённый аккаунт теряет API-доступ; refresh-сессии отозваны |
| C-10 | Пользователь школы A запрашивает ID школы B | Нет cross-tenant доступа; ответ не содержит данных другой школы |

### D. Ученики и зачисления

| ID | Действие | Ожидаемый результат |
|---|---|---|
| D-01 | Администратор открывает список учеников класса | Список соответствует активным зачислениям и выбранной школе |
| D-02 | Добавить карточку ученика без зачисления (QA) | Карточка видна администратору, но ученик не появляется в классных журналах |
| D-03 | Добавить корректное зачисление (QA) | Ученик появляется в соответствующих журналах в пределах дат зачисления |
| D-04 | Передать некорректную школу/класс или повторную связь | Сервер отклоняет неверную связь без частичной записи |

### E. Журнал оценок

| ID | Действие | Ожидаемый результат |
|---|---|---|
| E-01 | Учитель назначенного класса открывает журнал | Контекст класса, предмета и периода доступен |
| E-02 | Добавить оценку с валидным учеником/предметом/датой | Оценка появляется в списке после сохранения и перезагрузки |
| E-03 | Повторить тот же уникальный ключ работы | API возвращает конфликт; дубликат не появляется |
| E-04 | Изменить оценку/комментарий/дату | Новые значения сохраняются, список обновляется |
| E-05 | Удалить оценку в QA | Строка исчезает из активного списка; действие отражено в аудите/soft delete |
| E-06 | Ввести оценку вне диапазона 1–5 или чрезмерный комментарий | Валидация блокирует запись и показывает ошибку |
| E-07 | Открыть период без записей | Пустое состояние и доступные действия отображаются без сломанной таблицы |
| E-08 | На телефоне открыть журнал и форму | Таблица прокручивается или адаптируется, поля доступны и не обрезаны |

### F. Посещаемость

| ID | Действие | Ожидаемый результат |
|---|---|---|
| F-01 | Администратор/назначенный учитель выбирает класс и дату | Появляются все ученики, зачисленные на эту дату, и текущие отметки |
| F-02 | Поставить present/absent/late/excused и примечание (QA) | Все допустимые поля сохраняются; повторное чтение возвращает те же значения |
| F-03 | Нажать «Все присутствуют» | Все видимые селекторы получают `present`; данные отправляются только после сохранения |
| F-04 | Сохранить некорректный статус или незачисленного ученика через API | Сервер отклоняет запрос; транзакция не оставляет частичных изменений |
| F-05 | Сохранить дату за границами учебного года | Операция запрещена |
| F-06 | Ученик открывает свой журнал | Видит только собственные записи; controls редактирования отсутствуют |
| F-07 | На мобильном экране открыть таблицу | Имя, статус, примечание и кнопки доступны при горизонтальной прокрутке |

### G. Ведомость поведения

Перед этим разделом убедитесь, что у QA школы ровно 10 критериев. Сначала экспортируйте шаблон; не подменяйте заголовки пользовательскими названиями.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| G-01 | Получить criteria API и проверить конфигурацию | Ровно 10 элементов, устойчивый порядок; названия соответствуют школьному Excel-шаблону |
| G-02 | Администратор выбирает класс/год/период и генерирует ведомости (QA) | Созданы ведомости активных учеников; повторная генерация не создаёт дубликаты |
| G-03 | Выбрать контекст класса/периода | Таблица содержит все 10 критериев, итог, оценку/вердикт и действие |
| G-04 | Заполнить неполный набор баллов | Неполное состояние сохраняется, итог не считается полным |
| G-05 | Заполнить все баллы в пределах max_score | Backend пересчитывает итог и вердикт; значения UI/API совпадают |
| G-06 | Отправить балл выше максимума/критерий другой школы | Сервер отклоняет некорректные данные; чужая школа не затрагивается |
| G-07 | Учитель без can_score открывает/меняет лист | Редактирование запрещено сервером |
| G-08 | Учитель с can_score меняет значения назначенного класса | Сохранение успешно и отражено в аудите |
| G-09 | Открыть ведомость на ширине мобильного телефона | Те же 10 критериев остаются доступны через горизонтальную прокрутку; можно оценить и сохранить |
| G-10 | Экспортировать CSV/Excel | Все названия критериев и столбцы согласованы с текущим экспортом; нет потерянных колонок |
| G-11 | Школа имеет 0, 9 или 11 критериев | Создание/экспорт блокируется объясняющей ошибкой/сообщением, а не молча исчезающей таблицей |

### H. Администрирование и таблицы

| ID | Действие | Ожидаемый результат |
|---|---|---|
| H-01 | Администратор открывает админку на desktop | Отрисованы вкладки, таблицы/пустые состояния, формы и статусы |
| H-02 | Проверить вкладки справочников, пользователей, приглашений, аудита | Каждая вкладка открывается и показывает согласованные данные |
| H-03 | Смоделировать отказ одного `/admin/{resource}` (DevTools mock/QA proxy) | Остальные таблицы остаются доступны; ошибка только в проблемной секции; есть retry |
| H-04 | Смоделировать отказ `/admin/users`, `/admin/invites` или `/admin/audit` | Неудачный раздел сообщает ошибку, прочие разделы продолжают работать |
| H-05 | Попробовать открыть админку с учётной записью не-admin | UI скрывает маршрут и backend отвечает отказом на прямой запрос |
| H-06 | Проверить мобильную ширину | Навигация вкладок прокручивается, таблицы доступны и не перекрывают элементы |

### I. Excel импорт/экспорт

Только QA база, предварительный backup и явное разрешение на запись.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| I-01 | Экспортировать workbook | Файл открывается; листы, заголовки и критерии присутствуют |
| I-02 | Не изменяя данные, импортировать экспортированный workbook | Импорт завершается без неожиданных изменений; экспорт повторно сверяется |
| I-03 | Изменить одно безопасное тестовое значение и импортировать | Изменяется только ожидаемая запись; summary указывает обработанные строки |
| I-04 | Изменить обязательный заголовок / дать неизвестную ссылку | Импорт отклоняется с номером листа/строки и без частичного commit |
| I-05 | Импортировать файл выше лимита или неверный формат | Запрос отклоняется до обработки; сервер не завершается аварийно |
| I-06 | Проверить ячейки с `=`, `+`, `-`, `@` в экспортируемом тексте | Значение безопасно экранировано от выполнения как spreadsheet formula |
| I-07 | Проверить поведение критериев и workbook | Все 10 колонок остаются такими, как в экспортированном шаблоне; custom title/code без согласования не переписываются |

### J. Регрессия браузера и API

1. В DevTools → Network выбрать один успешно работающий API-вызов и проверить HTTP status, запрос/ответ и auth заголовок без копирования токена в отчёт.
2. Проверить Console на uncaught exception и rejected Promise.
3. Перезагрузить экран после записи в QA и проверить устойчивость результата.
4. Проверить прямой URL/route без сессии и с каждым типом аккаунта.
5. Проверить desktop (ширина около 1366 px), планшет (768–1024 px), телефон (360–430 px), zoom 200% и keyboard focus для критичных controls.
6. При неудаче сравнить frontend request payload с DTO/backend validation, логи API и схему текущей QA БД.

## 4. Автоматические команды

Из корня репозитория:

```sh
go test ./...
go vet ./...
node --test web/js/api.test.mjs
```

Эти unit/статические проверки не заменяют функциональный тест UI и PostgreSQL integration test.

Полный integration сценарий demo API запускайте **только на изолированной подготовленной QA БД**:

```sh
TEST_DATABASE_URL='postgresql://.../qa_database?sslmode=require' \
  go test ./internal/api -run TestDemoTeacherInvitationAssignmentAndGradeWorkflow -count=1 -v
```

Скрипт проверки demo fixture запускайте только при `DATABASE_URL`, указывающем на отдельную disposable БД: он применяет миграции и записывает seed. `supabase db reset` разрушителен для целевой БД и здесь не предлагается как команда для production.

## 6. Критерии завершения

- Нет блокирующих ошибок входа/ролей, смешения школ, записи оценок и посещаемости.
- Администратор может читать и редактировать предусмотренные школьные журналы; ученик не получает чужие данные и не может писать.
- Ведомость поведения содержит согласованные с Excel 10 столбцов и корректно пересчитывает итог.
- Ошибка одного справочного запроса не скрывает все админские таблицы.
- Все созданные данные относятся только к QA и очищены либо база восстановлена утверждённым способом.
- FAIL/PASS выводы подтверждены evidence; все BLOCKED/NOT RUN перечислены отдельно.

## 7. Отчёт об ошибке

Для дефекта приложите: ID сценария, роль (без email/ФИО), предпосылки, точные воспроизводимые шаги, ожидаемый/фактический результат, browser/viewport, method/path/status, короткое сообщение ошибки, commit/migration version. Удалите access/refresh токены, DSN, email, ФИО, табельные номера и реальные оценки. Не выкладывайте пользовательские данные или экспорты в публичные issues.
