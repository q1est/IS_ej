# Обзор продукта и архитектуры

## Назначение

Электронный школьный журнал предоставляет веб-интерфейс ученикам, учителям, классным руководителям и администраторам школы для работы с учебными годами, классами, периодами, учениками, оценками, посещаемостью, ведомостями поведения, проектами и аудитом.

Репозиторий: [q1est/IS_ej](https://github.com/q1est/IS_ej). Production URL интерфейса, описанный в README проекта: <https://q1est.github.io/IS_ej/>. Наличие сайта не означает доступность или актуальность API: проверяйте health endpoint отдельно.

## Архитектурная схема

```text
Браузер (web/)
  └─ HTML/CSS и ES modules (web/js/)
      └─ HTTPS REST API (cmd/api, internal/api)
          ├─ auth / identity / role access
          ├─ students / grades / attendance / behavior / admin
          ├─ audit
          └─ PostgreSQL (Supabase)
```

- Frontend — статические файлы, не подключается напрямую к PostgreSQL или Supabase.
- Backend — Go HTTP server; маршруты доменов регистрируются в `internal/api/server.go`.
- Хранилище — PostgreSQL. Структурные изменения описываются SQL-миграциями.
- Аутентификация — access-токен и rotating refresh-сессия; защищённые API проверяют пользователя, статус, роли и школу на сервере.
- Аудит — критические операции записываются в журнал событий.

## Главные пользовательские потоки

1. Администратор настраивает школу, учебные годы, классы, периоды, предметы, учеников и зачисления.
2. Администратор отправляет одноразовое приглашение на нужную роль; пользователь активирует аккаунт.
3. Администратор назначает учителю предметы и классы или классного руководителя.
4. Учитель в рамках назначения вносит и корректирует оценки.
5. Учитель и классный руководитель отмечают посещаемость разрешённых классов; администратор управляет журналом на уровне школы.
6. Администратор настраивает 10 критериев поведения, создаёт ведомости класса и разрешает уполномоченным учителям выставлять баллы.
7. Администратор экспортирует/импортирует данные Excel; операции проверяются сервером и журналируются там, где предусмотрено.

Точные матрицы прав и исключения описаны в [ролях и функциональности](roles-and-features.md), маршруты — в [API](api.md).
