# Ограничения и дальнейшее развитие

Этот документ отделяет подтверждённые свойства исходного кода от функций, которые требуют проверки на конкретном окружении. Пункт в roadmap не означает, что дефект уже воспроизведён.

## Операционные проверки, не доказуемые только из репозитория

- Production схема может отставать от исходников: особенно важно проверить migration посещаемости и критериев поведения.
- `GET /healthz` проверяет процесс и DB ping, но не проверяет доступность всех relation/table для каждой feature.
- Интеграционный тест зависит от изолированной QA БД и fixture; при отсутствии `TEST_DATABASE_URL` он не исполняет end-to-end действия.
- Проверки гостевого браузера не доказывают доступ после авторизации. Используйте специально подготовленные тестовые аккаунты и функциональный сценарий.
- Excel пользовательской школы мог иметь свой исторический набор заголовков. Сравнивайте с актуальным экспортом и согласованным шаблоном; не выводите заголовки из другого окружения.
- Production CORS, secrets, mail flow, backups/restore и Netrun/GitHub Pages статус должны проверяться в кабинетах платформ отдельно.

## Технические ограничения, требующие решения/приоритизации

1. **Тестовое покрытие браузера.** Имеющийся JS test проверяет в первую очередь восстановление session/refresh API client. Расширить UI tests для частичных загрузок, таблиц, ролей и адаптивности, а также сделать устойчивую локальную browser automation без production credentials.
2. **Управление средами.** Документировать disposable local/QA/prod DSN boundaries и автоматизировать проверки, которые не могут случайно использовать production host.
3. **Миграционная дисциплина.** Определить подтверждаемую схему применения/фиксации migrations и health/readiness check по версии схемы без DDL на старте API.
4. **Auth и delivery.** Продумать MFA администратора, безопасную доставку приглашений email, password recovery, audit/alerting и rate limiter для многорепличного deployment.
5. **Производительность и UX.** Оценивать paging/filtering для больших школ, журнал оценок/аудит/Excel limits, keyboard accessibility и мобильные таблицы.
6. **Privacy/compliance.** Официально утвердить retention, backup encryption, incident response, data export/deletion и юрисдикционные требования для ученических данных.

## Условия закрытия пункта

Добавлять пункт как «исправлено» только после изменений кода/миграции, автоматических тестов (где возможно), выполнения релевантного сценария на QA и ссылки на подтверждение. Production rollout фиксировать отдельной release записью; не считать локальный PASS production PASS.
